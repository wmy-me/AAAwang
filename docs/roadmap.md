# 开发路线图

更新日期：2026-11-02。以下为用于讨论和拆解任务的阶段草案，不是一次性执行清单。每个阶段可拆成多个小任务；阶段编号不等于 AI 任务编号。具体 SDK、协议版本、字段与命令在相应任务开始前核对。

| 阶段 | 目标与主要交付 | 验收重点 | 当前状态 |
| --- | --- | --- | --- |
| P0 工程初始化 | React、uv/FastAPI、三个 Java 骨架、可选数据库与运行说明 | 独立启动、健康检查、锁文件和报告 | 已有代码与初始化报告；浏览器交互未验证 |
| P1 最小 Agent 能力验证 | 模型配置与最小真实调用；通用 MCP 接入；一个 Java 模拟查询工具；最小工具调用循环 | 实际握手、发现、调用与错误处理；LLM 根据工具结果回答；服务配置可扩展 | 进行中：001 普通文本已提交；002 MCP 待执行；工具调用未验证 |
| P2 任务与对话基础 | 先完成最小登录、认证与用户隔离，再实现会话、消息、任务版本、后台执行、SSE 与持久化 | 双用户不能互访私有资源；刷新可查看、条件不串任务、取消与故障明确 | 未实现 |
| P3 首条采买闭环 | 教师奖品情景、按需追问、候选与来源、预算数量校验、结构化方案、网页展示与修改 | 同一用例完成检索、规划、保存和调整；多智能体按需协作 | 未实现 |
| P4 真实信息与更多采买场景 | 地图、搜索、天气，以及衣物、二手、饮品和经营采购 | 分清公开信息与模拟报价，正确处理未知项；替换或新增 MCP 服务做兼容验证 | 未实现 |
| P5 投稿与知识检索 | 图文投稿、审核发布、关键词与语义检索、引用、下架同步 | 发布可检索、下架不推荐、答案能追溯到作品 | 未实现 |
| P6 出行规划与场景联动 | 交通酒店候选、每日行程、预算时间检查、美食与采买关联任务 | 日期与预算调整正确、任务条件隔离 | 未实现 |
| P7 集成与交付 | 管理功能补齐、全应用部署、评估数据、论文与演示材料；按情况开展 Android | 环境可复现、典型场景验证、权限与恢复检查、效果评估 | 未实现 |

基础权限随 P2 建立；商家管理、投稿审核等管理功能跟随对应阶段交付，不统一拖到最后。P4 至 P6 的顺序可根据数据与实际依赖调整。

交易执行、结算预览、用户确认、模拟订单与支付单列为后续扩展，不混入当前查询规划主线。预留方案 ID、来源平台、商品规格和数量等结构化信息，方便未来衔接。

## 下一步讨论的范围

001 模型最小连通已提交，报告记录真实文本请求成功。下一步为 [002 MCP 接入](vibe%20coding/002-mcp-integration.md)：一个 Java 模拟工具与通用 Python 客户端真实联调。完成后另立 003 验证 LLM 工具调用，再推进 P2。无需先完成三个 Java 平台的业务后台。

## 任务与阶段的关系

每个具体开发或验证步骤在实施前建立 `vibe coding/NNN-主题.md`，写清属于哪个阶段、起始提交、前置条件、范围和完成标准。实施后在 `reports/NNN-主题-report.md` 记录结果，并同步 `progress.md`。

历史初始化任务是 000。后续编号按实际讨论结果递增，不提前把整份路线图细化为大量未经核对的执行文档。

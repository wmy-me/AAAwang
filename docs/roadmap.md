# 开发路线图

更新日期：2026-11-03。以下为用于讨论和拆解任务的阶段草案，不是一次性执行清单。每个阶段可拆成多个小任务；阶段编号不等于 AI 任务编号。具体 SDK、协议版本、字段与命令在相应任务开始前核对。

| --- | --- | --- | --- |
| P0 工程初始化 | React、uv/FastAPI、三个 Java 骨架、可选数据库与运行说明 | 独立启动、健康检查、锁文件和报告 | 已有代码与初始化报告；浏览器交互未验证 |
| P1 最小 Agent 能力验证 | 模型配置与最小真实调用；通用 MCP 接入；一个 Java 模拟查询工具；最小工具调用循环 | 实际握手、发现、调用与错误处理；LLM 根据工具结果回答；服务配置可扩展 | 已完成：001 至 003 均有真实验证与报告 |
| P2 任务与对话基础 | 先完成最小登录、认证与用户隔离，再实现会话、消息、任务版本、后台执行、SSE 与持久化 | 双用户不能互访私有资源；刷新可查看、条件不串任务、取消与故障明确 | 已完成：004–014 均有实现与报告；014 已选任务多轮网页对话与助手消息持久化已验收 |

| P5 投稿与知识检索 | 图文投稿、审核发布、关键词与语义检索、引用、下架同步 | 发布可检索、下架不推荐、答案能追溯到作品 | 未实现 |

基础权限随 P2 建立；商家管理、投稿审核等管理功能跟随对应阶段交付，不统一拖到最后。P4 至 P6 的顺序可根据数据与实际依赖调整。

交易执行、结算预览、用户确认、模拟订单与支付单列为后续扩展，不混入当前查询规划主线。预留方案 ID、来源平台、商品规格和数量等结构化信息，方便未来衔接。

## 任务与阶段的关系

每个具体开发或验证步骤在实施前建立 `vibe coding/NNN-主题.md`，写清属于哪个阶段、起始提交、前置条件、范围和完成标准。实施后在 `reports/NNN-主题-report.md` 记录结果，并同步 `progress.md`。

历史初始化任务是 000。后续编号按实际讨论结果递增，不提前把整份路线图细化为大量未经核对的执行文档。

产品交互方向：自然语言任务为入口，Agent 依据当前操作和已知条件按需追问或提出可校验的动态表单；预算、人数和数量不作为所有场景的固定必填项。020 先收口模型能力决策，动态表单另拆编号任务，参见[动态表单设计](design/dynamic-task-forms.md)。

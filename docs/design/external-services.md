# 外部服务与免费接入清单

核对日期：2026-11-02。这里列的是后续候选与接入边界，不表示已开通账号、已完成对接，也不代表免费额度永久有效。实施前以服务后台的最新条款、额度、地区和许可为准。本项目以「先把模拟采买闭环做通，再接真实公开信息」为顺序。

## 怎么用、用在哪里

| 用户问题示例 | 数据流与输出 |
| --- | --- |
| 「帮我在附近找买礼品的店，顺便规划过去的路线」 | 主 Agent 根据意图调用地点/路线工具 → 高德返回 POI、地址、距离和城市交通路线 → 展示候选与来源；商品种类、价格、库存仍由模拟数据提供，并标记模拟。 |
| 「下周出门穿什么，行程能否放在室外」 | 天气工具取得预报及时间范围 → 与日期、地点、偏好结合给建议 → 预报之外的日期显示未知；不把历史/远期预测写成确定天气。 |
| 「为学校奖品采购查一些公开资料」 | Java 商品 MCP 提供模拟候选 → Tavily 搜索公开规格或资料并保留网页链接和查询时间 → 校验预算数量 → 来源分开显示，公开网页不自动变成报价。 |
| 「推荐本地吃饭和顺路景点」 | 高德搜索周边 POI/计算路线 → P5 发布的帖子经权限和状态过滤后检索引用 → 规划每天顺路行程；实时排队、菜单价若无可靠来源显示未知。 |
| 「订酒店与车票，顺便做旅游预算」 | 高德负责地面路线，天气负责计划条件 → Java 出行 MCP 的酒店/车票仅作为演示候选 → 预算标记估算与模拟；实际下单/可订判断待有合法数据源再做。 |

## 工程接入边界

1. **统一入口。** 保留 `tool registry → 外部 MCP/HTTP 适配器 → 领域数据` 的结构。后端根据意图和用户授权，只向 Agent 暴露适用工具；为结果保留 `source`、`observed_at`、`is_simulated`、必要的未知字段与单位。网页来源需要可追溯链接；用户私有数据检索必须按用户和发布状态过滤。
2. **MCP 不是免开发。** 当前 Python 客户端验证的是已配置的 Streamable HTTP Java 模拟服务；配置虽有 `auth_token` 字段，但客户端不支持带认证的外部服务，且尚未支持 stdio、OAuth 或自动适配各服务工具参数。远端高德 MCP 使用 key，Tavily 需要其支持的认证流程；P4 增加保密配置、鉴权、超时/限流、错误分类、工具 allowlist、脱敏日志和端到端兼容测试。不要把 key 写进仓库或业务日志，尤其注意 URL 查询参数可能被记录。
3. **HTTP 不是 MCP。** Open-Meteo 可以作为 Python 内部 HTTP 工具，无须为统一形式而强行包装为 MCP。高德 POI/路线通常采用 GCJ-02 坐标，Open-Meteo 的经纬度输入需按其文档使用；跨服务联动时显式转换或先验证坐标来源。
4. **免费要可降级。** 限额、认证、超时或无结果时显示来源不可用/未知，不拿模拟价格冒充实时结果；对重复请求做缓存和限频，避免把一次 Agent 循环放大为不可控的外部调用。免费套餐仅覆盖符合条款的使用方式，项目公开部署或商业化前重新核对。
5. **模型费用单列。** 已有 DeepSeek API 调用不因上述免费服务而自动免费。若以后要求全链路无外部调用费，再单独评估本地模型质量、机器资源及工具调用兼容性。

## 落地顺序与验证

- 当前按 [路线图](../roadmap.md)继续 P2 的 [006 私有任务与条件版本](../vibe%20coding/006-task-revisions.md)，再推进 Worker/SSE；P3 首条采买闭环先使用模拟 MCP 完成保存、修改和来源展示。
- P4 第一个外部 MCP 建议只接高德的地点搜索和路线，验收真实握手、发现/调用、鉴权、限流、失败回退、来源标识与两种用户任务；随后接天气或 Tavily，单项通过后再扩展。
- P5 再用现有 pgvector 和对象存储做投稿检索/图片；P6 在已验证地图/天气的基础上做行程，车票酒店继续模拟直到找到合规且可持续的真实数据源。
- 开始每项接入时新建编号执行文档，记录当时的服务版本、免费政策截图/链接、配置占位符、权限范围、验收用例和停止条件；实施后写报告。当前清单是设计候选，不能据此把 P4–P6 标记完成。

# 数据保护与幂等设计规则

- 更新日期：2026-11-03
- 性质：后续编号任务必须核对的工程规则；不是“以下功能已全部实现”的声明
- 当前证据：[认证契约](../../contracts/rest/auth.md)、[消息契约](../../contracts/rest/conversations.md)、[任务版本契约](../../contracts/rest/tasks.md)、[Run 契约](../../contracts/rest/runs.md)

## 1. 先盘点数据与操作

每个新增持久化字段、外部服务接入或有副作用的接口，在执行文档中说明：字段来源与敏感级别、谁能读写、存储/传输/日志处理、删除与备份影响；操作的业务唯一键、重复请求行为、并发冲突、外部失败和重试策略。源码中的实现与报告的验证要逐项对应，不能用“已加密”概括所有安全措施，也不能把数据库事务等同于外部调用 exactly-once。

## 2. 字段处理规则

| 数据 | 处理要求 |
| --- | --- |
| 账号密码 | 只保存经验证的慢速加盐密码哈希（当前 Argon2id），绝不记录明文或可逆加密密码；校验时使用正式认证路径。 |
| 登录会话秘密、重置/验证令牌 | 使用高熵随机值，服务端只保存可校验的摘要、有效期和撤销状态；Cookie 采用 HttpOnly、合适的 SameSite，生产通过 HTTPS + Secure 传输。不得把明文令牌写进数据库、日志、模型上下文或报告。 |
| DeepSeek Key、MCP/OAuth 密钥、第三方访问令牌 | 默认只在受保护的本地配置或部署密钥管理中使用，不进 Git、API 响应、Run 结果或日志；若业务确需长期保存第三方令牌，单独设计服务端可解密的静态加密、密钥隔离、轮换与权限，不使用密码哈希代替可恢复令牌。配置的 SecretStr 仅用于避免意外输出，不代表字段已加密。 |
| 手机、地址、证件等个人资料 | 按最小必需原则收集、限制归属和查询、避免进入模型和外部 MCP 的非必要上下文；确需存储敏感字段时评估字段级加密、备份与访问审计，密钥不能与密文保存在同一公开配置。展示/日志按用途脱敏。 |
| 内部 ID、外部平台订单号/商品号 | 一般保留可查询的标识符，必须关联平台、所属用户或任务、校验访问权限；不得把“有订单号”当作授权。只有当标识符本身能当凭据使用或包含敏感信息时，按令牌/个人资料升级保护。对外展示与日志按实际风险遮蔽，不默认把所有订单号不可逆哈希，否则无法对账。 |
| 普通任务条件、对话和 Agent 结果 | 由服务端归属过滤，最小化保存和传给模型/工具的字段；包含敏感资料时按其字段类别处理。当前 JSON/文本字段不是自动加密的。 |

传输与磁盘分别评估：本地回环 HTTP 开发配置不等于生产 TLS；数据库卷/备份是否加密必须由实际部署方案验证，不能仅凭 `SecretStr`、PostgreSQL、Docker 或 HTTPS 推断已启用。隐私数据不能写进测试快照和执行报告。

## 3. 当前已实现与未实现的边界

- `users.password_hash` 使用 Argon2id；`login_sessions.token_hash` 存随机会话秘密的 SHA-256 摘要，浏览器会话使用 HttpOnly Cookie；认证来自服务端，不接受模型提供的身份。
- 对话、任务和 Run 通过服务端当前用户归属查询隔离。任务版本采用 `expected_revision` 乐观并发；同文同 `client_message_id` 的消息重试返回原消息；Run 在同 task 下使用唯一 `idempotency_key`。
- 当前没有正式订单表、外部订单号或第三方令牌持久化，也没有对任务条件/对话/结果统一实行字段级加密。不能声称这些字段已加密，也不能假定模型输出、工具结果或外部服务声明自身可信。

## 4. 幂等与并发规则

有副作用的用户操作或 Worker/外部调用可能被浏览器重试、网络超时、重复点击、进程恢复或多 Worker 并发触发。新增操作按风险给出明确的幂等边界：

| 操作类别 | 首选约束与结果 |
| --- | --- |
| 创建消息、任务、Run、方案、投稿、上传等 | 对会重复提交的创建操作，使用稳定的客户端请求 ID 或业务唯一键，明确作用域（至少用户/资源/操作）；在数据库建唯一约束并在事务中复用原结果。相同键不同实质请求应返回冲突，不得悄悄复用或覆盖。若某操作明确允许重复（如主动创建新版本），写清差异与用户触发方式。 |
| 修订条件、调整数量、改变方案、取消等 | 对同一资源执行版本检查或条件更新，确保并发不会丢失修改；重复取消应保持同一终态。版本控制解决并发覆盖，不能自动替代创建操作的幂等键。 |
| Worker 领取、状态变更、持久化结果、事件 | 使用唯一业务键、租约/所有权、fencing token 和状态前提；结果与终态事件尽量同事务提交。过期 Worker 的迟到写入必须拒绝；Run 的重复完成不得生成多份结果/终态事件。 |
| 外部 MCP 写入、下单、支付、发票等 | 只有明确授权并设计完成时才开放。优先使用外部服务提供的幂等键/请求号并保存映射；外部请求超时或 Worker 崩溃后状态不明时先查询/对账再决定重试，不能仅因为本地事务回滚就再次发起可能已成功的写操作。外部无幂等能力时采用人工确认、待核对状态或其他受控补偿方案，不承诺跨系统 exactly-once。 |
| 只读查询 | 可按成本、时效和限流策略重试；缓存键应包含用户权限与必要任务版本，不能把不同用户的私有结果混用。 |

幂等键须由可信范围和请求内容校验，不以禁用按钮作为唯一保证；防重复记录的有效期若有限须写明。检验并发请求、相同键相同内容重试、相同键不同内容冲突、提交成功但客户端未收到响应后的重试、Worker 失租/重试，以及外部状态不确定的分支。真实外部服务无法测试时，报告明确列出替身验证和未验收项。

## 5. 后续任务如何引用

每份新增编号任务先阅读本规则，对涉及的字段与操作给出具体决策；不涉及敏感字段或写副作用时简述“不适用”和依据。业务契约写清实际请求字段、唯一性作用域、错误码和重试行为；迁移建立必要数据库约束，测试覆盖有价值的重复/并发/失败场景；执行报告区分设计、代码、替身与真实验证。此规则不授权立刻新增订单、支付、加密框架或重写 004–012；发现现有实现不满足具体业务约束时，以新的编号任务修复并记入进度。

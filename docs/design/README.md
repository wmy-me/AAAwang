## 结论的使用方式

| 类别 | 当前记录 |
| --- | --- |
| 架构方向 | 012 已实现最小主从委派；完整 P3 协作遵循[Agent 执行与预算规则](agent-execution-rules.md)，其上限待评估 |
| 工具方向 | 统一工具管理与执行边界；业务职责和接入方式分别分类 |
| MCP 方向 | Java 模拟服务验证通用接入，后续可接其他服务；保留协议结果与领域候选 |
| 意图方向 | 上下文规则、一次模型结构化判断、后端校验；不先堆叠独立识别 Agent |
| RAG 推荐基线 | PostgreSQL + pgvector，结构切分，关键词与向量召回、融合和重排 |
| 待评估参数 | 分块长度、重叠、召回数量、模型型号、索引与分类阈值；不是已经验证的最优值 |
| 已实现与验收 | 单独查看 [进度](../progress.md)、源码和任务报告，不能由设计标题推断 |

## 与执行文档的关系

P1 的 001–003 与 P2 的 004–[006 任务条件版本](../vibe%20coding/006-task-revisions.md)均已有实现和报告。P2 已验证私有对话、任务和条件版本的归属隔离；run/Worker、SSE 与意图路由仍需后续任务。投稿检索与出行按路线图阶段实施，不因新增设计文档就提前开工。

每次实施前，将相关设计拆成一个有前置条件、具体范围、验收与停止条件的 [编号任务](../vibe%20coding/README.md)。接口与数据库字段确定后，同步维护契约和设计，避免多个文档长期保存不一致的正式 schema。

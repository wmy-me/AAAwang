# 文档导航

本目录将项目目标、设计参考、AI 执行任务和完成证据分开维护。文档描述的计划不等于代码已经实现。

## 阅读顺序

1. [项目定位与主线](overview/project.md)：做什么、为谁做、Java 模拟服务的定位。
2. [开发路线图](roadmap.md)：按能力递进的阶段、交付物与验收目标。
3. [Agent、Tools、RAG 与意图设计](design/README.md)：本次讨论的专题结论与待评估参数。
4. [当前进度](progress.md)：核对代码后的状态、证据与当前待讨论事项。
5. [AI 执行任务入口](vibe%20coding/README.md)：Claude、Codex 开始工作时应读取的规则。
6. [开发指南](guides/development.md)：安装、启动与环境问题。

## 分层

| 目录 | 内容 | 使用方式 |
| --- | --- | --- |
| `overview/` | 项目定位、功能范围和计划书 | 了解产品目标 |
| `design/` | 架构、流程、数据与协议设计参考 | 实现具体任务前按需阅读 |
| `vibe coding/` | 给 Claude、Codex 等 AI 的编号执行任务 | 只执行用户本次指定的任务 |
| `reports/` | 对应任务的实施与验收报告 | 区分完成、失败、未验证 |
| `guides/` | 开发、运行、部署操作指南 | 随实际工程更新 |

`roadmap.md` 管长期阶段，`progress.md` 管当前事实；机器可读的接口定义放在仓库根目录 `contracts/`，设计解释放在这里。

## 后续迭代

讨论需求与最新代码 → 编写一个范围明确的执行任务 → Claude/Codex 实施与验证 → 提交报告、更新进度 → 再读取仓库决定下一步。不会因为路线图中有后续阶段就自动执行。

## 1. 模型与接口

Alembic `20261102_0003` 新增 `tasks` 和 `task_revisions`：

- task 归属 conversation，保存稳定 ID、domain、目标、当前 revision 指针和时间戳。
- revision 归属 task，保存单调版本号、完整 JSON 条件快照、可选变更说明和创建时间。
- `(task_id, revision)` 唯一；对话和任务删除时逐级级联。
- 任务和历史均有确定分页排序索引。

新增五个接口：在对话中创建和列出任务、读取当前任务、读取历史、提交新 revision。所有权经 `Conversation.owner_id` 限定；不存在与越权统一 404。请求拒绝 owner/user 等额外字段。

首版 domain 为 `shopping` 与 `travel`。条件是完整快照而不是 patch，只允许契约定义的预算、人数、物品、数量、目的地和日期字段；未知字段、嵌套值和错误类型返回 422。缺失字段表示尚未提供。相同快照的明确提交仍创建下一版本。

新 revision 使用数据库条件更新 `current_revision = expected_revision`。版本抢占与新快照在同一事务提交；过期基线返回 409 和当前版本，不能覆盖并发修改。

## 2. 快速测试替身

SQLite StaticPool 仅用于快速 API 边界测试，不作为最终并发或持久化证据。新增 4 项聚焦测试覆盖：

- 同一对话 shopping/travel 两任务条件互不影响，旧快照保持不变。
- 相同快照创建新版本，过期版本返回含当前 revision 的 409。
- B 对 A 的创建、列表、读取、历史和修订均为 404；新客户端恢复 A 的数据。
- 匿名、伪造身份、非法 domain/字段/类型/日期、分页和跨站写请求边界。

## 4. 边界

- 没有 run、Worker、租约、重试、取消、SSE 或 LangGraph 检查点，任务目前不能执行或恢复。
- 不从聊天消息自动识别任务，不调用 LLM/MCP，不生成方案或助手消息。
- 条件 schema 是首版小集合；未来增加领域字段需同步迁移策略、契约和验证，不能接受任意 JSON 作为执行参数。
- 未做高并发压力测试；已用 PostgreSQL 两个真实并发请求验证同基线至多一个成功。
- 网页没有任务或版本界面，本轮未修改或构建网页。

## 1. 实现

- 复用 OpenAI Python SDK 3.42.1、DeepSeek `deepseek-flash` 配置和既有安全错误映射；001 普通文本入口保持可用。
- 从受信配置中的服务 ID连接 MCP，真实发现工具及输入 schema。只有 `search_products` 允许列表成员会暴露给模型。
- 模型函数名由限定身份和 SHA-256 短摘要稳定生成，只包含供应商允许字符；同名工具位于不同服务时名称不同。模型不能提供服务 ID或 URL。
- 首轮允许直接回答或一个 tool_call。工具参数必须是 JSON对象，并经 `jsonschema` 4.26.0 按 MCP schema 验证后才调用。
- 最多两次模型请求和一次 MCP 调用，总截止时间默认 90 秒；未知/未授权、多调用、重复调用、无效参数和过大结果会安全终止。
- MCP 结构化结果优先回传，缺失时才使用有界内容块；回传内容最多 12,000 字符，并通过原始调用 ID关联。
- `check_tool_loop.py` 针对本轮 shopping 示例额外核对 `source_type=mock`、来源服务、实际候选名和对应价格。通用执行器不硬编码商品结构。

## 3. 受控测试

工具循环的模型与 MCP 替身只用于边界测试，不替代上一节真实联调。9 项聚焦测试覆盖：

- 合法单调用的参数校验、MCP 路由、调用 ID回传和最终回答。
- 模型直接回答时不调用 MCP。
- 未知/未授权工具、非法 JSON、schema 越界参数和首轮多个调用均在执行前拒绝。
- 第二轮重复调用被拒绝，不执行第二次 MCP。
- 正常空结果作为成功结果交回模型，不伪装成故障。
- 不同服务 ID下同名工具映射为不同模型函数名。

既有 MCP 测试继续覆盖工具 `isError`、连接失败、初始化超时和未知服务/工具的事实分类；这些错误由工具循环原样传播，不包装成空结果。

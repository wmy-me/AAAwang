## 问题与目标

当前 coordinator 的表单提示仅允许 `item/people/quantity/budget`，`modules/forms/service.py` 的字段注册也仅有这四项。虽然模型决定是否提出这些字段，仍无法针对不同用户需求提出地点、日期或偏好等条件。这与用户希望自然语言驱动、场景字段不固定的目标有差距。

本任务让模型能从受控的**控件类型**中提出场景相关的动态字段，前端按 schema 展示，用户确认后安全保存到当前任务的新 revision，并在后续对话和 Run 中可用。字段名称和标签不限于购物四项；不接受任意 HTML、脚本或未经验证的数据。保留 021/017 旧行为、历史任务和预算计算。

## 实施边界

1. 设计有限且可扩展的字段 schema，首批支持短文本、数字、金额、日期、单选与多选；地点可用短文本承载明确的城市/地点，不声称已有地图定位控件。字段 ID、标签、说明、选项、值类型、数量、长度和数值范围均受服务端校验，拒绝任意 UI 代码、脚本、非法 ID、重复字段及超限内容。保留原有四字段的兼容语义和金额复算。
2. 将用户确认的扩展条件按任务与 revision 版本化保存，记录字段 schema 与值；明确与已有条件的合并、同名冲突和历史读取策略。必须复用或扩展现有一致性/幂等机制，避免不同场景条件混写；用户身份、服务 URL、工具权限、密钥、支付信息不能被模型字段写入。考虑数据库迁移和已有 revision 回填/兼容。
3. coordinator 根据目标和已知条件建议字段；用户未要求或字段不必要时可直答、探索或调用已授权工具，不能为每个任务强制表单或固定预算、人数、数量。服务端校验模型输出，不能通过表单绕过 Run 前门禁。支持用户编辑/确认，未经确认的模型推断不得当作硬约束。
4. 前端安全渲染受支持控件，展示字段标签、原因和合法范围，允许用户确认；旧表单和旧任务继续可读。不得在前端计算或信任硬金额约束；表单字段不足以表达的情况自然语言追问或标记不支持。
5. Agent 的流程、工具权限、共享预算和现有 MCP 继续沿既有路径；不以特定场景写死后续工具调用。暂不实现出行全流程或知识库。

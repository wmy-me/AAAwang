# NNN：任务名称

> 任务模板，复制并填写后使用，本文件不可直接执行。

- 状态：草案
- 所属阶段：P?
- 起始分支与代码提交：待填写
- 前置任务及证据：待填写
- 对应报告：`docs/reports/NNN-主题-report.md`

## 1. 问题与目标

描述当前具体缺口，以及完成后用户或开发者能观察到的变化。

## 2. 先读哪些内容

列出相关代码、执行规则、设计和契约的具体路径。执行者先核对当前源码，记录文档与代码的差异。

## 3. 本次范围

列出需要实现或验证的内容、允许涉及的模块，以及本次边界。不要将整份项目路线图复制进任务。

## 4. 方案、接口与依赖

说明关键输入输出、错误行为、配置、数据来源与模拟标记。涉及模型或 MCP 时，执行前核对所选版本、协议与认证；凭据走本地配置，不写入仓库或报告。

涉及 Agent 时先读[Agent 执行与预算规则](../design/agent-execution-rules.md)：写明本次角色是否采用有界 ReAct、可见工具、共享模型/委派/工具/时间上限、修正次数、停止原因与未完成结果的呈现方式；记录哪些数值属于本次已实现并验收，哪些仍为待验证提案。

## 5. 数据保护与幂等决策

先读[数据保护与幂等设计规则](../design/security-and-idempotency.md)。列出本次新增/变动字段的敏感度、归属与读写权限、存储/传输/日志/备份处理；列出有副作用操作的幂等键作用域、数据库约束、重复请求结果、并发冲突、取消/失租和外部状态不明时的重试方式。无需处理的项目写明不适用及理由；不得直接声称订单号均需加密、数据库事务保证外部 exactly-once。

## 6. 执行步骤

按依赖列出步骤；给出可自行决定的常规实现细节，避免无意义的反复确认。

## 7. 验收标准

每项写为可观察的结果，覆盖正常行为与相关失败场景。明确哪些必须用真实服务验证、哪些可用测试替身。选择与改动相称的检查，不编写只镜像实现的测试。

## 8. 完成后的文档

- 更新相关契约与开发说明。
- 创建对应报告，包含代码基线、改动、实际命令与结果、验证模式、未验证项和阻塞原因。
- 更新 `docs/progress.md` 和本目录索引。
- 只有满足验收标准才标记完成；存在重要缺口时注明部分完成或受阻。

## 9. 停止条件

完成上述目标并汇报后停止。额外发现的问题记录为后续事项，不自动进入下一个任务。提交、推送及 PR 按当前用户授权与仓库约定执行。

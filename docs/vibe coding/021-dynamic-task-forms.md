## 1. 范围与边界

本任务仅实现动态表单提议、服务端校验与网页渲染，不回填或替代 020 尚未完成的真实浏览器刷新、真实 Worker 取消/失租/超时和 Java `verify` 验收。动态表单是自然语言任务的补充入口，不把预算、人数或数量设为所有购物请求的固定必填字段。

保留 017 的目标/条件一致性门禁、旧固定字段和历史 Run 兼容；字段提议、用户确认值、任务 revision 和 Run 仍按 owner、task、revision、幂等键绑定。模型不能生成 HTML、脚本、数据库列、工具权限、支付字段或用户身份字段。

## 2. 实施要求

1. 主协调只输出受限 JSON 表单 schema：稳定字段 ID、控件类型、标签、单位或选项、是否必答、提出原因和合法范围；后端按注册场景白名单校验。
2. 表单建议与用户原文、已确认条件、模型推断和来源分开保存；未经确认的模型建议不能成为预算、数量或金额硬约束。
3. 表单提交复用任务 revision、Run 和消息幂等语义；过期 revision、越权字段、重复字段、非法范围和未知控件必须拒绝。
4. 网页分别展示待确认字段、已确认字段和自然语言输入；刷新后从服务端重读，旧任务固定字段仍可编辑。
5. Agent 按当前操作和已知条件动态决定是否追问；无预算可以先探索，有可靠硬约束时才要求确认，不把固定表单流程写成每轮必经路径。

## 3. 验收

| 场景 | 通过标准 |
| --- | --- |
| 无预算探索 | 没有预算时可以先查询或给探索建议，不写入默认金额 |
| 动态字段 | 目标变更后生成与当前操作匹配的新字段，旧版本字段和 Run 保持可读 |
| 多目标追问 | 一句话包含多个目标时，分别提出必要字段，不越权合并任务 |
| 双入口 | 表单提交与自然语言回复产生相同的受控 revision/Run 语义 |
| 校验与隔离 | 未注册字段、非法值、过期版本、重复请求和跨账号读写均被拒绝 |
| 回归 | 020 的真实能力决策、预算摘要、地点/商品证据和旧固定字段继续可读 |

先用替身覆盖 schema、版本、幂等和权限边界，再用真实 DeepSeek、PostgreSQL、独立 Worker 与浏览器验证代表性自然语言任务。报告区分模型建议、服务端校验、替身测试和真实联调；未验收不得标记完成。

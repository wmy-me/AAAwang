## 3. 实施范围

1. **身份与导航。** 在同源 `/api` 代理下提供注册、登录、`/api/me` 刷新恢复和退出。使用服务器 HttpOnly Cookie，前端不保存或展示 Session Cookie、DeepSeek Key、数据库密码。未登录只展示认证入口；401 时清理页面私有状态，403/503 给出可理解错误。界面只加载当前用户的对话、任务和 Run。
2. **对话与任务。** 左侧显示真实私有对话列表，可创建并选中对话；主区域显示所选对话下的购物任务。创建任务时提交明确的 `goal`、`domain=shopping` 与可选 `conditions`（预算、人数、数量、物品），未知保持缺失而非填 0。任务版本只通过正式 revision API 完整替换，用户能看到当前版本与条件；遇到 409 时重新读取，不静默覆盖。此轮不由前端猜用户消息对应的旧任务；如果同时展示手工消息，要说明它们不自动触发 Agent。
3. **Agent Run。** 用户在明确选中的购物任务上发起 `execution_type=shopping_agent`，携带当前 `expected_revision` 和稳定的客户端幂等键；重复点击或网络重试不得产生无意重复 Run。显示 queued/running/completed/failed/cancelled，提供协作式取消和旧 Run 历史列表。Run 与版本、条件关联可见；不得让用户在客户端指定 MCP URL、工具或 owner。
4. **事件与结果。** 使用浏览器原生 SSE 接入已有私有事件流，保存已收到的最后 sequence，并在断线/刷新后通过 `after` 补读或重连；终态后获取 `GET /api/runs/{run_id}/result`。如 SSE 不可用，允许有界状态轮询和重试提示，但不得把空事件当作成功。展示回答、`decision_type`、是否委派、MCP 调用次数和来源；仅在真正查询模拟商品时标记“模拟商品/模拟价格”，无来源不得伪称已查到。失败、空结果和追问分别显示，禁止仅以 `completed` 就渲染伪造方案。
5. **页面质量。** React + TypeScript 保持按功能划分的 API 与组件，适配桌面与窄屏；采用清楚的侧栏、任务详情、状态/结果区域，键盘可操作、加载/错误/空状态清晰。保持样式与组件适度简洁，不引入未使用的全套 UI 框架或新增隐藏的假数据。

## 4. 数据与可靠性约束

- **事实来源**：`conversations` / `tasks` / `runs` / `shopping_run_results` 的服务端 API；浏览器内存状态仅作展示缓存。刷新后以当前用户重新拉取；不能从 localStorage 复原私有回答或凭空生成历史消息。历史结果按 Run ID 与所属 task 呈现。
- **并发与幂等**：创建 Run 时用 task 当前 revision，收到 409 显示冲突并刷新；修订条件不改变已创建 Run 的旧快照。每次新运行使用新幂等键，重试同一次请求复用原键；客户端请求超时后以原键重试同一 Run 请求或查询已有 Run，不在不确定时生成新键。取消后不能把迟到 SSE 误显示为新的成功。对话/任务创建目前没有服务端幂等键，本轮不得自动重试其不确定请求；先刷新列表供用户核对，并在报告中记录剩余风险。若要支持这些创建操作自动重试，须先补服务端幂等契约和数据库唯一约束；前端禁用按钮不是服务端保证。
- **权限与输入**：写请求沿用可信 Origin，输入长度与数值按现有服务端 schema 校验；前端校验仅作用户提示。网页不直连 shopping-mcp，也不缓存 API Key 或自行绕过后端身份。答复作为文本安全渲染，不能把模型或 MCP 返回正文作为可信 HTML。
- **后端范围**：优先复用 004–012 API；确需修复契约与实现之间的小差异时加最小回归。此次不增加自然语言自动建任务、自动识别意图、助手消息写入、方案/候选业务表或新 MCP 工具。图状态及 Worker 继续由现有后端处理。
- **配置**：根目录 `.env` 的项目 PostgreSQL、DeepSeek 和 MCP 保持本机配置；本次不需要 MySQL、Redis、MinIO 或其他服务密钥。所有真实测试记录用隔离账户创建并清理，保留项目命名卷。

## 目标

用户在对话中提供位置并提出“附近找某类商铺”时，Agent 可按需使用已配置高德 MCP 的真实周边搜索，以具体坐标为中心返回有来源的地点结果。城市关键词搜索继续工作。需要澄清位置时通过自然语言询问，不新增强制表单；普通对话和不需要地图的任务不强制调用地图。

目标场景仅作示例：用户说“帮我看看天安门附近有哪些文具店”，系统依据地址得到位置并搜索周边；用户也可直接提供坐标。“教师奖品”不是特定场景或触发条件，不能硬编码行业关键词。

## 开始前

读取根目录 AGENTS.md、CLAUDE.md（存在时）、当前地图配置、工具注册/白名单、MCP 客户端、意图与 Worker 调用路径、地点卡片/持久化及 018 报告。核实用户现有 `backend/.env` 及实际配置来源但不打印凭据；不覆盖配置、不启动备用 Compose。复用现有高德 MCP、Worker、Run 预算和认证；真实服务和网络不可用时不以替身结果宣称通过。

## 实施

1. 在现有 MCP 客户端动态发现工具及 schema，允许并适配高德真实的周边搜索（通常为 `maps_around_search`）以及必要时地址转坐标的地理编码工具（通常为 `maps_geo`）；以实际服务发现的名称/参数为准，在现有服务白名单中显式配置。工具允许集与参数由后端验证，模型不得指定任意 URL 或绕过认证。分别构建正确参数，不能把文本搜索的 `keywords/city/citylimit` 参数原样发给周边搜索。
2. 用户给出坐标时直接检索；给出足够明确的地址/地标时按需先转换坐标，多个匹配无法安全选择时澄清；缺少位置则对话追问。网页定位如已有可用实现则复用，不新增强制定位授权或强制输入控件。缺半径使用可配置的合理默认，范围限制由后端设定；不随意声称实际距离或默认参数是用户给出的。
3. 将能力接入 032 意图层之后的现有 coordinator 和生产 Worker 路径，允许模型根据当前需求选择文本搜索、周边搜索或无需地图；不新增并行执行链，不绑定某个采购示例。需要组合商品与地点时仅在现有能力范围内按需执行，不承诺店铺库存或商品来自该店，不强制所有购物任务使用地图。
4. 复用现有地点结果、聊天消息/卡片、用户隔离、持久化/SSE、取消和共享预算；按实际返回保留名称、地址、坐标、来源和查询时间等可用字段，不编造距离、营业状态、库存或价格。区分高德真实结果和 shopping MCP 模拟商品；无结果或服务失败时明确说明。工具调用超时及地理编码、周边查询分别计入现有预算。
5. 提供必要配置示例及简短使用说明，复用现有地图 Key，不要求新增其他模型或服务。031 模型下载/记忆真实联调、LLM Wiki、出行 Agent 和界面大改均不在本任务；不得改变默认禁用记忆状态。

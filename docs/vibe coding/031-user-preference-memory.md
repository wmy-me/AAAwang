## 1. 目标与完成效果

基于 **Mem0 开源版 SDK**，在现有纯对话、Worker 和 ContextBuilder 基础上实现跨会话的用户偏好记忆。用户通过自然语言记住、查看、修改或删除明确指定的偏好；后续同账号会话按需召回。当前用户明确要求优先于旧记忆。

示例：用户说“记住我不吃辣”→ 保存；新会话询问餐厅时可参考；“忘记我不吃辣”→ 删除，后续不再召回。示例用于验收，禁止硬编码关键词或场景。

**不在本步**：自动将所有对话写入长期记忆、上传文档/RAG、长会话摘要、出行 Agent、大规模目录重构。教师奖品是业务场景而非 Skill；本步不要求重构场景文件或调整现有业务流程。

## 2. 开始前与配置

读取根目录 `AGENTS.md`、`CLAUDE.md`（存在时）、030 报告、上下文设计及本任务；检查最新会话、Worker、预算、认证和数据库代码，确认实际依赖版本与运行路径。不能覆盖用户本地改动。

- 优先使用当前已有 PostgreSQL；先核实目标实例支持并已启用 pgvector，检查角色权限、维度和现有表；不得把已有 PostgreSQL 等同于 pgvector 已可用。禁止清库、删除卷或改动其他项目数据。
- Embedding 与 DeepSeek LLM 是不同依赖。优先选择与 Mem0 支持版本兼容的本地中文多语言 Embedding，明确模型名、向量维度、下载和 CPU/GPU 配置；也允许配置已有兼容的远程 Embedding。不得以 DeepSeek Key 充当 Embedding。模型下载可能需要网络和本地空间。
- 显式配置 Mem0 LLM、Embedding、pgvector 持久化及历史存储，核实所选版本的接口和依赖；固定可复现的依赖版本，避免使用默认 OpenAI Key、临时 Qdrant 或临时 SQLite 路径。记录所有实际存储位置及备份要求；若历史信息存到 SQLite，必须使用明确的持久路径并纳入备份，不得藏在临时目录。
- 复用现有 DeepSeek 配置作为 LLM，确认 SDK 支持及预算计数如何覆盖额外调用。Mem0 开源 SDK 不需要 Mem0 云服务 Key；DeepSeek 和远程 Embedding 可能产生费用，发送到外部模型的数据会离开本机。
- 优先复用现有 `backend/.env` 和项目配置入口，新增参数写入相应 `.env.example` 和说明，绝不提交或打印真实 Key、密码和完整连接串。保留 Compose 作为备用，不自动启动新的同类容器。
- 若 pgvector、模型下载、凭据或权限不可用，完成不依赖该条件的代码和检查，明确记录唯一阻塞、所需配置与恢复命令；不得伪称真实持久化闭环通过，也不得悄悄改用内存或临时存储。不要索取或输出密钥原文。

## 3. 实施要求

### 3.1 边界和接入

- 实现薄的记忆服务适配层，封装 Mem0 创建、检索、列表、更新、删除，方便替换实现；业务层和 Agent 不直接分散依赖 SDK。结合当前项目生命周期管理初始化，避免每个请求重复建立模型/连接。
- Mem0 实际存储与用户管理 API 的唯一事实来源要明确，避免另一套业务表与 Mem0 的内容双写后不一致。若需要本地操作记录、映射、幂等键或迁移，说明权威数据、事务边界、失败补偿与兼容性。保存必要来源、创建/更新时间；不可将 SDK 版本不支持的字段假设为已有。
- 新增依赖与配置示例、最小运行说明，以及需要的数据库迁移；说明 pgvector 扩展权限、集合/命名空间、向量维度与模型变更后的重建策略。不得覆盖现有用户、会话或任务数据。

### 3.2 对话写入与管理

- 由模型在授权工具或等效受控接口中识别用户明确的“记住、查看、修改、忘记”意图；经服务端校验后执行，并以自然语言报告结果。覆盖自然语言同义表达，不要求固定句式、固定表单或每轮强制写记忆。
- 首版只保存用户明确要求保存的稳定偏好。当前任务的预算、人数、位置等仍是任务/会话条件；模型猜测、临时信息及一般聊天不自动写入。
- 同一记忆的修改和删除需限定归属；意图不明确或命中多条时通过对话澄清，不能擅自删除全部。对重复提交、重试和并发定义可操作的幂等/冲突策略；不声称外部调用天然 exactly-once。
- 用户可通过聊天查询、修改、删除；不强制制作新的设置页，但接口及适配层应允许后续增加管理界面。用户当前明确要求优先于历史偏好。

### 3.3 召回、上下文与预算

- 从认证上下文取得 user ID，由服务端注入并校验；模型、前端参数和工具参数不能指定其他用户。每次操作和召回均强制 owner 约束；仅凭向量集合过滤不足以替代后端授权。
- 相关时按当前问题检索少量记忆，注入 030 的上下文构建和现有 Worker 路径；不把所有记忆或整段历史每轮传给模型。记忆是低可信数据，不能改变 system 提示、工具白名单、权限或预算。
- 显式控制召回数量、内容长度、超时及错误处理；记忆不可用时普通对话可继续，用户主动要求写入/删除失败时清楚反馈，不谎称成功。
- Mem0 提取、检索及 Embedding 若产生外部模型调用，接入现有 Run 共享预算或实现可核算的有界预留；记录如何计数、超时和停止。禁止绕过 030 的预算/Worker 租约与 fencing，外部调用结果应在提交前复核执行权；取消或租约丢失后的写入需要明确处理。不要为了记忆另建绕过 Worker 的对话执行链。

### 3.4 隐私、删除和持久化

- 默认拒绝保存密码、API Key、验证码、证件号、支付凭据等敏感数据；日志不输出密钥或完整敏感内容。
- 删除后该用户的正常查询和召回不能再返回该记忆；清理可控缓存和衍生索引。说明 Mem0 历史/审计、数据库备份的保留或清理方式，不承诺未实现的彻底物理擦除。
- 说明实际向量库、Mem0 历史及配置分别保存在何处和如何备份。服务重启后记忆应可恢复；不能使用进程内或临时路径作为正式持久化。

## 4. 精简验收

只做覆盖本阶段关键结果的验证，不要求全量回归、重复浏览器验收或故障测试矩阵：

1. **一条真实主流程**：使用真实 PostgreSQL/pgvector、所选 Embedding 和 DeepSeek，通过现有对话入口保存一条普通偏好；新建同用户会话并确认可检索使用；删除后确认不再检索到。验证持久存储能在相关服务重启后读取。记录所用组件、核心结果和实际入口（API 或网页均可），不输出敏感内容。
2. **少量针对性检查**：第二账号无法读取或修改第一账号记忆；本轮明确要求优先于旧偏好；临时预算不会自动存为长期记忆；记忆服务故障时普通对话可继续且写入失败有明确反馈。适当复用既有测试，不为了凑数量增加镜像实现的测试。
3. 对本次修改运行相关检查和必要迁移验证；记录真实调用与替身的区别。不能访问必要服务时按受阻报告，不把模拟或未执行当作真实通过。

## 1. 当前状态与本轮目标

019 的单个 `capability_router` Run 已真实调用高德地图 MCP 和 Java 模拟商品 MCP，分别保存地点、候选和方案；但当前能力选择仍依赖服务端结构化规则，`DIRECT` 分支未形成无工具直答，能力元数据缺输入 schema、独立超时和预算，模型/工具尝试也没有贯穿主从节点的共享硬预算。本轮补全这些约束，让主协调从**当前任务允许的能力**中作结构化模型决策，并让代码在每次调用前核验与计数。

保留 018 的地点 API、019 的能力/Run 快照和历史结果。模型不能选择 URL、用户身份、服务 ID 或任意工具名。地图真实地点与 Java 模拟商品保持不同来源，金额继续由服务端复算。本任务不接入新外部 MCP、天气、网页搜索、RAG 或下单工具。

## 2. 实施要求

1. **决策契约**：主 Agent 输入仅包含受信任务版本、本轮用户消息、必要的待答上下文和当前可用能力描述。输出固定 schema：直答、追问、使用商品能力、使用地点能力或两者组合，附受控参数与简短原因。后端验证 schema、任务/版本、必要条件及能力可见集。歧义或无有效选择走追问/安全失败；无工具直答不创建虚假的商品或地点证据。
2. **注册与发现交集**：能力元数据记录稳定 ID、允许 Agent/任务域、输入 schema、只读级别、调用超时、结果类型和预算消耗；可用工具为注册策略、已配置服务、实际 MCP 发现结果和当前任务权限的交集。模型只看交集，执行前再次校验；配置关闭、工具下线或 schema 不兼容时明确不可用。Graph 按受控决策/状态转移，避免把地图与商品固定串接。
3. **共享预算**：定义单 Run 模型请求、专业委派、每类 MCP 尝试、总远端调用、墙钟截止时间与图递归兜底。结合实际 019 测得的 3 次模型、2 次 MCP 给出首版可行硬上限和余量；跨主 Agent、信息发现、组合分支使用同一预算对象/持久化计数，失败和重试也计入。调用**之前**预占，取消、失租、超时或耗尽立即停止新调用，记录终止原因；并发分支不能各自重置上限。与旧 Run 的空能力快照兼容。
4. **执行与存储**：保持一个用户轮次对应可追踪的 Run/终态，决策、工具、结果和 assistant 回复的归属及幂等一致；重放或旧 Worker 不能绕过预算与 fencing。必要迁移采用新版本，不能改写历史迁移。外部内容不能修改权限或下一轮工具集合。
5. **网页与报告**：网页分别显示直答、追问、地点证据、模拟商品和组合结果，刷新后可重读。报告按真实/替身区分模型决策、工具发现、预算计数、浏览器和数据库证据；若某真实服务不可用，保持未验收标记。

## 与后续动态表单的衔接

用户已明确要求以自然语言为主，并由 Agent 按任务状态提出需要的字段。预算、人数和数量不能作为所有购物请求的固定必填门槛；未知值保持未知，探索与直答可以先进行。020 的模型能力决策与校验遵循[动态表单设计](../design/dynamic-task-forms.md)，本轮只完成能力决策，不把尚未实现的表单渲染标记为通过。旧固定字段和方案接口保持兼容，动态表单在后续独立编号任务落地。

## 1. 问题与目标

001 只证明 DeepSeek 普通文本请求成功；002 只证明 Python 与 Java 模拟服务的 MCP 初始化、发现、调用成功。当前 `call_deepseek` 只返回文本，尚无模型工具调用。目标是让一条真实采买问题经历“模型根据发现的工具 schema 产生调用 → 后端验证并调用 MCP → 模型根据返回结果回答”，并留下可复核的真实联调证据。

本轮可观察成果为一个命令行检查入口；不要求建立网页聊天或多 Agent。

## 3. 本次范围与边界

- 复用已有 DeepSeek 配置、OpenAI SDK 和 MCP 客户端；现有普通文本检查与异常行为保持可用。可将共同的模型客户端构建和安全错误映射抽出，避免并行复制一套模型配置。
- 从配置中的 `shopping` MCP 服务真实发现 `search_products`，保留原始描述及输入 schema；按本轮允许列表向模型暴露该只读工具。命令行脚本可以选择示例服务及问题，通用接入层不硬编码 Java 商品类型。
- 建立模型工具名与 `service_id:raw_tool_name` 的稳定映射；模型名称需满足供应商约束且不能与其他服务同名工具混淆。发现不等于授权，未列入允许集合的工具不能执行。
- 实现最小非流式、有限轮次的工具调用：模型可直接回答，或提出一次允许的工具调用；后端解析和校验参数，实际调用 MCP，按模型协议将工具结果及调用 ID关联回模型消息，再取得自然语言回复。
- 示例可使用 `shopping:search_products`，但执行器应按映射路由，不把“看到任意 tool_call 就固定查商品”写死。代码组织以最小可维护实现为准，不强制先建 LangGraph 图。
- 仅处理共享的只读模拟目录；不引入用户会话、任务持久化、账号身份、写入工具或真实交易。Java 002 的协议与模拟数据保持原样，除非发现必要的兼容缺陷并说明。

## 4. 执行与结果约定

1. 连接受信配置的 MCP 服务并发现工具；将所选 schema 转换为模型工具接口。若 schema 不兼容，明确拒绝或有记录地适配，不能静默删除关键校验；后端依据发现的约束和服务端规则复核模型参数，不能信任模型生成的 JSON、服务 ID 或 URL。
2. 一次运行有明确的模型请求次数、工具调用次数、总截止时间和单次超时上限；默认首版最多一次 MCP 调用及后续一次模型回复。返回多个调用、重复调用、未知工具名、无法解析的参数或超过上限时明确失败或安全终止，不执行额外调用。
3. MCP 正常无匹配是成功的空结果；参数无效、工具 `isError`、连接失败、协议失败和超时分别保留事实。不得将失败包装成“查无商品”或让模型编造候选。模型没有调用工具时应正常解释这一分支，但不把它算作工具联调成功。
4. 只将完成回答所需的有界工具结果与来源交回模型。检查最终回答中的商品、价格和来源能对应实际工具返回，不存在的商品或超出返回范围的价格不能作为有效验收；模拟结果明确称为模拟商品及模拟价格。不得仅靠提示词声明就把无依据输出记作通过。
5. 密钥、认证头、完整供应商异常正文与不必要的个人输入不写入日志或报告。凭据只经本地环境配置，脚本不接受任意用户输入的 MCP URL；无密钥或 Java 停服时 API 的 `GET /api/health` 仍可独立启动。

建议新增 `backend/scripts/check_tool_loop.py`，从 `backend/` 运行：

```bash
uv run python scripts/check_tool_loop.py --service shopping --prompt "我想买一盒彩色铅笔，单价不超过15元，有什么模拟商品？"
```

参数与文件名可按最终实现微调并更新指南。成功输出至少概述服务、发现与实际调用的工具身份、模型是否真的发出 tool_calls、模拟候选摘要及最终回答；失败返回非零退出码。不要在仓库中固化真实密钥、外部响应或运行时日志。

## 5. 验收与证据

| 检查 | 通过标准 | 证据模式 |
| --- | --- | --- |
| 真实完整链路 | 独立 Java shopping-mcp 与真实 DeepSeek：发现工具、模型发出结构化 tool_call、通过 MCP 查询、模型收到结果并回答；记录协议、模型、工具身份及安全摘要 | **必须真实联调**；001、002 的独立成功不可替代 |
| 工具选择与映射 | 模型不调用工具时不产生 MCP 调用；未知/未授权工具、多调用超限不执行；服务 ID 映射不串线 | 聚焦测试可使用受控模型与 MCP 替身 |
| 参数与返回 | 合法参数执行；非法 JSON/schema/服务端非法参数不伪装成成功；无匹配返回空集合；工具错误、停服、超时明确区分 | 聚焦测试；至少正常场景真实联调 |
| 回答真实性 | 模拟来源和价格标记清楚；只使用实际返回候选，空结果或故障时不虚构结果 | 真实联调输出人工核对加聚焦检查 |
| 回归 | 001 文本检查的相关测试与 002 MCP 测试继续通过；Ruff、编译、锁文件检查通过；若修改 Java 再做受影响模块 Maven 验证 | 记录实际命令与结果 |
| 独立启动 | 不配置密钥或不启动 Java 时 API 仍可导入/启动；脚本按需报错 | 本地检查 |

真实模型可能对某次示例选择直接回答；此时调整明确需要商品信息的问题再验证，但不得伪造模型工具调用，也不要无界重复烧费。若凭据、供应商接口、网络或 Java 环境阻塞，报告受阻项、已完成的替身测试及重试条件，不能标记完整通过。

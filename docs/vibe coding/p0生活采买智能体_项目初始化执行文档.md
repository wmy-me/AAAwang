## 1. 给 Claude 的任务

请在当前工作目录，为“生活采买智能体”初始化一个包含 React 网页、Python 后端和三个 Java 服务的代码仓库。

本轮完成目录组织、框架依赖、配置模板、最小启动入口、健康检查和开发说明。完成框架启动验证后停止，不进入业务开发。

遵守以下范围：

- Python 统一使用 **uv** 管理版本、虚拟环境、依赖和运行命令。
- 网页使用 **React + TypeScript + Vite**。
- Python 主后端使用 **FastAPI**；安装 **LangGraph** 基础依赖，暂不编写图、Agent 或工具调用。

- 主体采用一个仓库、多个子工程；Python 未来的 API 与 Worker 共享同一个 Python 工程，不给每个 Agent 建服务。
- 不默认存在可复用的 Java 项目，不擅自下载或迁入其他业务仓库。
- 不需要用户提供模型、地图、搜索、数据库云服务等真实凭据。

本轮的“可启动”是指依赖安装完成后，网页、API 和三个 Java 应用可以分别启动。**本轮不要求模型对话、MCP 联调或后台任务运行。**

## 4. Python 框架初始化

### 4.1 工程与依赖

采用 `src` 布局，Python 包名统一为 `life_agent`。例如，在项目根目录且确认 `backend/` 尚未初始化时，可以使用：

```bash
uv init --app --package --python 3.12 --vcs none --name life-agent backend
```

若本地 uv 命令选项存在版本差异，先查看 `uv init --help`；以本节规定的目录与包名为目标，不必机械套用脚手架默认结构。不要为了匹配示例覆盖现有工程。

在 `backend/` 中添加：

```bash
uv add fastapi "uvicorn[standard]" pydantic-settings langgraph
uv add --dev ruff
uv sync
```

本轮只需要这些应用与开发依赖。暂不安装 ORM、向量库客户端、模型提供商 SDK、LangChain 集成包、Redis、任务队列或 Python MCP 客户端。

要求：

- 保留有效构建系统，让 `uv sync` 后可以正常导入 `life_agent`，不依赖手工修改 `PYTHONPATH`。
- 删除或调整脚手架自动生成的问候入口，避免与 `main.py` 冲突。
- 提交实际生成的 `uv.lock`，不提交 `.venv/`，不用 `requirements.txt` 替代 uv 依赖管理。
- 使用 `pydantic-settings` 读取应用名称、开发环境与日志级别；设置合理开发默认值。
- 创建 `backend/.env.example`。不把空白模型密钥声明成启动必填项，不在启动时访问模型或地图。
- 保留 FastAPI 自带的接口文档入口；本轮无须统一业务响应封装、登录中间件或自定义异常体系。

### 4.2 唯一 API

实现 `GET /api/health`，通过 `APIRouter` 接入主应用。建议返回：

```json
{"status":"ok","service":"life-buy-agent-api"}
```

这里仅表示 API 进程可以响应，不表示数据库、LLM 或 MCP 已经接通。

应用启动不依赖 PostgreSQL、三个 Java 服务或任何 API Key。不要新增聊天、任务、用户、商品、投稿、订单等接口，即使是固定返回值也不新增。

### 4.3 启动与基本检查

在 `backend/` 中：

```bash
uv sync --locked
uv run ruff check src
uv run python -m compileall -q src
uv run uvicorn life_agent.main:app --host 127.0.0.1 --port 8000
```

另开终端检查 `http://127.0.0.1:8000/api/health` 和 `/docs`。这里只做框架静态检查、导入和启动验证，不编写业务测试。

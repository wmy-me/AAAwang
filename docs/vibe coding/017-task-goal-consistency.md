## 1. 问题与目标

真实 REV2 验收中，`task.goal` 仍写“25 名学生、总预算 200 元”，当前 `revision.conditions` 则是 `people=25, budget=180`。服务端按 180 元复算正确，但任务卡和 Agent 输入同时出现 200 与 180。现有 revision 接口只能改条件，无法改目标；Run 可在未确认冲突时启动。

本轮让目标描述可以随任务修订形成不可变快照，用户编辑条件或目标时能够看到明确冲突并修正或确认，随后 Agent 读取同一版本的目标与条件。确认不能使旧的 200 元重新进入有效提示词；必要时把旧原文留作历史，并生成与 180 元一致的当前目标描述。旧 Run 继续绑定原始快照，旧方案金额不回写。

## 3. 实施要求

1. **版本化目标**：将当前有效目标描述与条件绑定到同一 `TaskRevision`。新增修订请求可提交目标描述和完整条件快照，`expected_revision` 乐观并发不变。创建任务建立版本 1 的目标快照；已有 revision 迁移时以当时可得的 `task.goal` 填充，并明确历史目标无法准确重建时的标记，不伪称旧目标为真实历史。任务卡、修订列表、Run 输入从同一版本读取；若保留 `task.goal` 作为兼容字段，只作为当前版本投影并在同一事务更新。旧 Run 读取和旧 API 行为兼容。
2. **冲突检查**：在服务端对购物目标中可明确识别的人数、总预算与 `conditions.people/budget` 检查矛盾。数字、中文单位和常见预算表达应有可验证样例；无法可靠解析或字段缺失时标为“不确定”，不得凭关键词猜测一致。检查结果指出字段、目标值、条件值和原文片段，不能仅靠前端判断。结构化 budget 始终是金额复算依据。
3. **确认或修正**：编辑条件与目标时在网页展示服务端冲突。用户可将目标修改到与条件一致，也可明确确认以结构化条件为准；确认必须形成可审计的当前版本决议，模型实际输入只含不矛盾的当前目标与结构化条件。例如旧文“200 元”保留在历史，当前描述使用确认后的“180 元”。未确认的明确冲突保持可读取和可编辑，不得启动新的购物 Agent Run。避免靠全局文字替换悄悄改写与预算无关的数字。
4. **Run 前门禁与竞态**：在手动创建 Run 和已选任务聊天 turn 触发 Run 的服务端路径执行同一检查。若用户提交基于旧 revision 的确认或条件修订，返回 409 并提供当前版本；若明确冲突尚未解决，返回包含冲突信息的业务错误且不排队、不扣模型/MCP 预算。检查与版本绑定在同一事务或等价原子边界完成，不能先查再被并发修订绕过。Worker 使用 Run 绑定的目标与条件快照，旧 Run 重试仍按其原版本执行，但不得把后来目标投影混入提示词。
5. **权限、幂等与展示**：目标修订只允许 owner，第二账号仍为 404；与既有 revision 乐观锁、聊天回合 `client_turn_id` 和 Run `idempotency_key` 相容。刷新后当前目标、冲突决议、版本历史一致；展示当前预算 180 时任务卡不继续称“预算 200”。不记录密钥或无关敏感对话，不向模型发送仅供审计的过期目标。

## 4. 验收

| 场景 | 通过标准 |
| --- | --- |
| 历史 200 → 当前 180 | 以 016 保留的验收任务或隔离副本复现：冲突在任务卡和接口可见，未处理时手动 Run 与聊天 turn 均不能排队；修正或确认后当前目标、条件、Agent 输入一致为 180，生成方案预算仍为 180 |
| 新任务与旧数据 | 新任务目标/条件同版；旧任务及旧 Run/方案可读取，历史目标迁移不冒充精确旧快照 |
| 并发与重试 | 两个基于同一 revision 的修订至多一个成功；确认后丢响应的重试不会造成重复版本或额外 Run；改条件后旧确认不适用 |
| 隔离与故障 | 跨账号读写不可见；冲突响应不调用 DeepSeek/MCP、不生成幽灵消息或 Run；Worker 不从当前 task 投影覆盖旧 Run 快照 |
| 真实闭环 | 真实 PostgreSQL 迁移及 `alembic check`、相关 Python 测试/Ruff、前端 lint/build、真实浏览器刷新与独立 Worker/DeepSeek/MCP 链路通过；报告区分替身与真实路径 |

实施顺序为契约和迁移、服务端一致性检查及双入口门禁、Worker 快照、网页确认/修正、真实联调。保存 [017 报告](../reports/017-task-goal-consistency-report.md)，同步进度、索引和路线图，再根据 016 §3.4 的验收事实标记 016 的剩余项是否补齐。完成后停止，后续阶段另拆编号任务。

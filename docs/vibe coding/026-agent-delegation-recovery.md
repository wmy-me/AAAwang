## 目标与范围

当前 `agents/discovery/graph.py` 限制一次委派；`_decision_from_message` 在模型单次返回多个 tool call 时直接报错，已有 JSON 格式修正不覆盖这个分支。用户的有效请求因此可能在第一次执行失败。本任务维持现有权限和共享预算，引入一次受控纠错，使模型能在不合法的委派响应后重新选择，再执行至多一个合法委派或直答/澄清。此任务不是实现任意多 Agent 并行或扩张工具权限。

保持用户目标、动态表单、已有 Agent/Skill/Tools 结构、Run 数据格式与采买金额计算。模型负责选择，服务端验证和执行；不得以固定商品、预算或路径替代决策。

## 执行前核对

先读根目录指令、025 报告、`agents/discovery/graph.py`、`core/budget.py`、工具循环、Worker 终态和相关测试。确认现有模型请求、委派、MCP、总远端调用和超时的共享预算及计数方式；检查 DeepSeek、PostgreSQL、独立 Worker、Java shopping-mcp 和浏览器环境；复用现有配置，勿输出密钥。

## 实施要求

1. 针对多个 tool call、未知委派名和参数不合法等模型决策错误，允许最多一次明确、有界的修正请求；首次错误不得执行任何 tool call。保留现有格式纠错语义，避免每类错误各触发一次无限重试。
2. 修正请求使用与模型协议兼容的消息序列，说明可选委派及约束；不能丢失必要的系统提示、当前目标或已确认条件。用户或工具文本不得扩大权限。修正后再次校验；仍不合法时明确失败，不静默执行第一项或跳过检查。
3. 纠错的模型请求在发送前预占同一 RunBudget；委派、MCP 仅在真正执行时计数。预算耗尽、取消、失租、超时均停止后续调用；失败和终态遵循现有 fencing。不得重置预算或暴露未经授权的工具。
4. 保留教师奖品 Skill 的现有行为，普通商品不强制加载。025 的一次委派限制是本阶段现有约束；以后是否支持多个委派另行设计。

## 验收与证据

| 场景 | 方法和预期 |
| --- | --- |

| 不合法响应 | 未知工具、无效参数、重复不合法及修正后直答/澄清，验证边界、终态和无额外工具调用；遵循模型消息协议。 |

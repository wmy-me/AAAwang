## 1. 为什么先做这一步

当前后端只有健康检查，尚无模型调用入口。先确认配置、模型适配、真实请求、结果解析与失败反馈能工作，后续再基于它接入工具和 Agent，便于区分问题来自模型、MCP 还是编排。

本轮交付是一个可以在本地运行的模型连通检查入口；不是网页聊天功能，也不是完整 Agent。

## 5. 实现要求

### 5.1 配置与默认启动

- 继续使用已有 Settings，不再建立独立的配置读取体系。
- 可采用 `LLM_PROVIDER`、`LLM_MODEL`、`LLM_BASE_URL`、`LLM_API_KEY`、`LLM_TIMEOUT_SECONDS` 等配置名；按所选协议调整。
- 默认没有模型配置时，FastAPI 和 `/api/health` 仍可启动。
- 只有显式执行模型检查时，才校验该供应商要求的配置并发起调用。
- 缺少配置时指出缺少哪个配置项，不输出配置中的秘密值。
- 密钥使用合适的秘密值类型，日志、异常和报告中均不输出密钥、认证请求头或完整敏感配置。

### 5.2 最小模型适配

- 使用可被未来异步 API 或 Worker 调用的入口；请求设置明确的超时。
- 先只实现普通文本输入和文本结果；后续可扩展消息及工具能力。
- 处理认证失败、不可用模型、超时、连接失败和空响应，给出可定位的错误信息。
- 初始化验证默认禁用自动重试，避免一次检查产生难以辨认的重复请求；如 SDK 自带重试，明确设置并记录。
- 依赖通过 uv 添加并提交真实生成的锁文件，不手工编写锁文件内容。
- 不在 import、Settings 构建或应用启动时创建远程请求。

### 5.3 本地检查入口

在 `backend/` 中支持类似命令：

```bash
uv run python scripts/check_llm.py
```

脚本从本地配置读取服务，发送一条简短固定提示，例如“请简短回复，确认你已收到测试请求”。检查实际响应成功且返回非空文本，不依赖回复必须逐字等于某一句话。

输出限于安全摘要：供应商、模型、成功或失败、耗时、少量固定测试回复，以及供应商提供时的 token 用量。没有返回用量时不要估算成真实值。失败使用非零退出码，不打印完整请求或异常对象中的凭据。

配置齐备时执行一次真实请求；如遇失败，先定位原因再进行必要复测，不循环大量请求。没有真实配置时也要说明脚本如何运行，但不能声称联调完成。

## 6. 验收标准

| 检查 | 通过条件 |
| --- | --- |
| 原有启动兼容 | 无模型配置时，原 API 入口正常导入，健康检查可用 |
| 必需配置校验 | 所选服务必需配置缺失时，检查入口清楚报错，不发起无效请求 |
| 真实调用 | 在执行机的有效配置下收到真实非空文本响应，记录实际结果 |
| 失败反馈 | 对相关认证、超时和异常响应行为有可复核结果；可用受控测试替身检查失败分支 |
| 秘密保护 | 示例、日志、输出和报告无真实密钥；本地环境文件未纳入提交 |
| 依赖与静态检查 | uv 锁文件有效，相关 Python 静态检查通过 |
| 文档 | 检查步骤、验证模式、未验证项和对应报告完整 |

不必为了验证错误分支故意对真实服务反复发送错误凭据。测试替身只能验证本地逻辑，不能替代“真实调用”这一项。

本任务普通文本调用成功，不代表模型工具调用、结构化输出、流式响应、MCP 或完整 Agent 已验证。

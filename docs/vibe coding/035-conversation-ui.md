# 035：简洁对话主界面与结果卡片

- 报告：`docs/reports/035-conversation-ui-report.md`。

## 用户目标

将当前网页调整为简洁的对话式界面，参考 GoGo/Codex 的布局思路，不要求复制外观：左侧会话列表和新建入口；中间对话消息；底部消息输入。普通回答是文本；有实际商品、地点、方案或来源数据时，结果跟随对应助手消息以适当卡片展示。用户无需先创建任务、手动填写固定条件或点击运行 Agent。

当前 `web/src/App.tsx` 中仍有采购大标题、task-section 和独立 artifacts/方案区域；先核对各区域在实际分支的显示条件及现有 API/消息卡片实现，再调整。历史任务、旧数据和已有 API 保留；历史方案可以通过对应消息查看或按需打开，不在聊天主界面常驻铺满。

## 范围

1. 重构现有页面主布局，优先复用消息、会话列表和结果卡片；移除主视图的采购专用大幅说明和默认常驻的任务表单、Run/方案工作台。旧能力若保留为折叠/明确入口，不可默认遮挡对话，不删历史数据和接口。
2. 新建/切换会话后即可输入自然语言；普通聊天、搜索和采购共用现有对话入口，追问通过文本继续。交互显示发送、运行和失败状态，复用已有取消/SSE 机制（如存在）；不将运行细节暴露为产品主要流程。
3. 消息中按所属 Run 展示实际可用的商品、地点、来源或方案卡片；若某类现有 API/结构不支持，在报告说明而不伪造数据。商品模拟来源要清楚；地点不暗示售卖模拟商品。无结构化结果只展示文本；刷新或切换后保持现有持久消息/卡片关联，防止上一个会话的结果串入当前会话。
4. 保留登录、退出、私有会话、历史记录和现有后台；按现有设计做适合桌面和窄屏的基本响应式布局，保持输入/按钮的可访问名称和错误提示。用户不要求独立设计稿，不新增组件库或第三方服务。
5. 不重构后端 Agent 或数据库、不实现 Wiki/出行、不下载模型、不运行 uv sync；031 Mem0 真实联调暂缓。前端环境如缺依赖，先利用现有环境工作；不能访问服务时报告说明，不把此问题当作实现完成证明。

## 精简验证

- 运行前端现有 lint/build，按变更范围检查，不要求后端全量。
- 一个最小前端实际使用流程：登录后新建对话，发送一条普通消息，确认对话展示与刷新；如果真实服务不可用，可用可控 API 结果完成界面检查，报告明确是替身。对卡片只检查一个已有结果的消息关联/刷新，不要求重复多场景浏览器矩阵。
- 检查空会话、窄屏基本布局和错误状态；无真实浏览器条件时如实说明，不将未执行写为通过。
- 更新报告、进度、索引，说明真实和替身验证及尚未实现的卡片。完成后停止，不开始 036。

## 3. 目标分层

以现有 discovery 的商品发现职责为入口，建议如下，路径可结合现有代码微调，报告解释实际映射：

```text
agents/
  coordinator/
    service.py                 # 协调入口和决策
    prompts/system.md          # 协调角色提示
  discovery/
    service.py                 # 商品发现入口
    graph.py                   # 现有图组装及条件边
    state.py                   # 图状态/结果契约
    nodes.py                   # 图节点
    prompts/system.md          # 商品发现角色提示
    skills/teacher_rewards.md  # 示例场景 Skill
  shared/
    prompts/                   # 通用来源、未知信息等公共提示
    skill_loader.py            # 受信 Skill 发现/读取与选择机制
```

1. 按职责提取现有图，迁移生产调用方；`shopping.py` 可短期作为明确的兼容导出，但只能有唯一真实实现。兼容旧 Run、导入、事件与结果。不要把确定性商品金额/数量校验搬给模型。
2. 系统提示词定义 Agent 身份、职责、停止及输出边界；公共片段保存共享规则；用户任务、条件和工具结果作为运行上下文单独注入。将购物图与 coordinator 的相关内联角色提示迁出，保留适配模型的消息角色及关键语义。提示资产由可信项目文件加载，明确加载失败行为、路径和版本；不得把用户或工具文本插入 system 指令。
3. Skill 是可复用的**场景指导**，包含名称、适用范围、触发/选择描述、指导内容和版本。首个 `teacher_rewards` 仅在教师奖品类目标相关时选择并注入；普通商品/天气/闲聊不可默认加载。采用可解释且有边界的选择机制：可让模型在服务端允许的 Skill 列表中选择，或使用受限且可测试的注册选择；报告说明实际机制及误选、无匹配和歧义处理。新增 Skill 应通过注册/元数据扩展，不修改图节点分支。Skill 正文是参考指导，不得赋予工具权限、修改系统规则、预算或用户身份；不把 Skill 当工具、MCP 或 Codex 自身的 Skill。
4. 允许模型在授权能力范围内判断直答、追问、委派及工具调用；保留现有有界图，不将商品→地图→天气或 Skill→工具写成固定路径。图条件边只约束合法流转。工具 schema/白名单、MCP 发现、来源、超时与共享预算由服务端代码负责。不得宣称本轮实现开放式多 Agent 或通用自主规划。
5. 从 Worker 迁出与购物 Agent 有关的提示构造/领域解析，Worker 保留领取、租约、取消、fencing、事务及执行分派；地图/天气是否迁移按最小必要原则处理。记录尚未解决的结构问题。

## 4. 验收与证据

| 验收项 | 方法与通过标准 |
| --- | --- |
| 生产链路与唯一实现 | 真实 Run 通过整理后的 discovery/graph 和提示加载入口；旧入口兼容，无重复生效的购物图或预算对象。报告提供调用链与迁移映射。 |
| 系统提示词 | 测试验证购物和协调提示从各自资产加载、角色和关键约束保留；缺失文件有可诊断错误，运行时用户/工具文本不能覆盖系统规则。 |
| Skill 按需生效 | 用教师奖品输入证明选中并进入实际模型请求；普通商品、天气和闲聊不注入该 Skill；未知/歧义安全处理。新增测试 Skill 能通过注册被发现，无需改 Graph 节点；检查恶意内容不能扩大工具白名单。 |
| 动态决策 | 直答、缺信息追问、无预算商品发现、地图和商品组合均按模型决策与授权能力执行，无固定全流程；保持共享预算、调用次数/终止原因，金额由服务端复算。 |
| 数据与安全 | 旧 Run/revision/历史结果可读；用户隔离、取消/失租 fencing 和工具越权拒绝继续成立。更改如涉及数据库须说明迁移、幂等及兼容，否则不新增迁移。 |
| 真实闭环 | 使用真实 DeepSeek、独立 Worker、PostgreSQL、真实高德及 Java 模拟商品 MCP，至少验证一个教师奖品采买和一个普通查询或地图+商品组合；报告 Skill 选择、来源、预算、Run 结果。数据标明真实地图与模拟商品。 |
| 网页与回归 | 浏览器登录、实际发起商品任务、查看结果并刷新；聚焦自动化覆盖图、Skill、权限/预算及现有天气/地图路径，执行后端测试、Ruff、前端 lint/build；已有有效证据可引用，受修改影响的路径需重验。 |

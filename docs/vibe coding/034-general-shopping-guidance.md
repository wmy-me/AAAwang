## 目标

将现有商品发现路径中的教师奖品专用指导解耦，使系统按用户自然语言处理不同采购需求。教师奖品只是普通例子，不创建专门场景包，也不依赖关键词触发；商品 Agent、可复用的方法指导、工具职责清晰。保持原有聊天入口和 Worker 链路。

## 实施

1. 先阅读 AGENTS.md、CLAUDE.md、当前 `agents/discovery`、`skills/loader.py`、`skills/teacher_rewards.md`、coordinator、tools 与相关测试，列清实际使用路径；基于现有设计实施，不另建平行 Agent/图或一批空目录。
2. 将跨需求有用的内容提炼为简短、可复用的采购/商品比较指导，或合理合并入现有可信角色提示；去除运行时按教师、学生、奖品等关键词加载专用指导的依赖。按实际引用调整/移除专用文件，不改变历史报告；不把预算、人数、品类设为所有请求必填。
3. Agent 根据当前对话及工具结果按需选择查询、比较、追问或直接回答，支持缺预算的探索型问题；不要固定商品→地图→规划路径。需要附近地点时使用已授权地图工具，不能声称真实商铺有模拟商品的库存、价格或销售关系。只在工具白名单、现有共享预算、租约、取消和 owner 约束下执行。
4. 保留纯自然语言对话与当前消息/结果契约，普通回答文字为主，有真实结构化商品或方案结果时复用既有卡片；不新增手工表单或重新设计整个网页。无结果或工具不可用时说明事实，不伪造价格或来源。
5. 不接入新的 Embedding 或服务，不运行 uv sync，不开展 031 真实联调，不实施 Wiki、出行 Agent 或 UI 大改。对未完成的既有复合意图处理及 033 端到端情况如实保留边界。

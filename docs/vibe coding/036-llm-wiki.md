- 状态：代码已实现，真实联调待补；上传、Worker 整理、API/网页入口和来源展示已完成，真实 DeepSeek/PostgreSQL/Worker/浏览器闭环未执行。

- 报告：`docs/reports/036-llm-wiki-report.md`。

## 目标

通过对话上传一个 Markdown 或纯文本文件，使用已有 DeepSeek 将其整理为可访问、带原文来源的私有 Wiki 页面，并在后续对话中根据该页面回答问题，展示来源。用户不必手工建立 Wiki 目录或填写复杂表单。

本步用现有 PostgreSQL 和 DeepSeek；不引入 Embedding、pgvector 向量索引、额外 Key 或第三方 Wiki 产品。LLM Wiki 是知识整理方式；检索第一版可用简单标题/关键词匹配和受控页面索引，效果不足应说明，不声称语义检索。PDF/Word、OCR、投稿审核、公共知识库、复杂 Wiki 图谱留待后续单独阶段。

## 开始前

读取 AGENTS.md、CLAUDE.md、当前对话与 Worker、消息持久化、认证、配置、数据库迁移和 035 网页代码；核对实际 API 和运行状态。复用现有 DeepSeek 及数据库配置，不输出或提交密钥、不启动备用 Compose。不得把 031 记忆替身或向量库称为已联调。

## 实施

1. 在现有聊天输入旁增加轻量文件上传入口，支持 .md/.txt，限制文件大小、数量和文本编码并给出错误。上传后用户可继续正常对话。仅处理用户明确上传的文本，不执行文件里的指令或脚本；不引入强制表单或后台管理大页。
2. 设计最小 PostgreSQL 数据及迁移：保存原文或指向实际可持久化文件的位置、owner、来源文件名、状态、创建/更新时间；保存 Wiki 页面标题、内容和来源关联、版本/状态。使用现有迁移方式，明确大小限制与失败状态，不要求额外对象存储。重启后数据仍可用。新增数据访问按当前认证用户隔离。
3. 通过现有 Worker/Run 和共享预算调用 DeepSeek 整理文档：有限长度、可配置超时与停止条件；保留来源文件和章节/片段定位，模型未返回时不要伪造页码或准确位置。资料是低可信输入，不可覆盖系统提示、权限和工具规则。失败时保留原文，显示失败或可重试；相同请求重试避免重复页面，明确外部调用不承诺 exactly-once。
4. 让主 Agent 通过注册的受控知识检索工具按需查询当前用户可访问的 Wiki 和必要原文；返回自然语言与来源链接/文件名。普通对话不必每次查库；没有相关资料时诚实说明。用户问原文精确内容或 Wiki 与原文冲突时回查原文。沿用现有消息、SSE 和引用卡片，不创建另一套执行链。
5. 用户应能在聊天中或轻量入口查看、删除自己上传的资料和相关 Wiki 页面；服务端强制 owner 校验，删除后不再可检索。更复杂的公共分享、多人编辑和历史版本管理不在本步。明确删除与备份保留边界。
6. 不实施向量数据库、全量文档类型、自动将聊天记为 Wiki、购物/地图改造、035 界面大改；Mem0 仍默认按现有配置关闭，不作为验收前置。

## 验证和收口

- 一条主流程：使用真实 DeepSeek 和项目数据库上传一份简短 Markdown → 生成 Wiki 页面 → 新会话提问并返回可核对的原文来源 → 删除后不再检索。API 或网页入口均可，不要求浏览器矩阵；如无法使用真实服务，先完成实现和必要检查，报告实际阻塞，不能标为真实通过。
- 少量必要检查：第二用户不可访问资料；上传的文本不能更改工具权限；普通聊天不强制查询知识库。相关前后端构建检查按实际改动运行，不跑额外全量套件。
- 更新进度、索引及 036 报告，分别记录真实/替身验证、文件存储位置、迁移和未完成项。完成后停止，不自动实施 037。

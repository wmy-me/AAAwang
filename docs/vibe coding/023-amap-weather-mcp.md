## 1. 问题与目标

018 已完成现有真实高德 MCP 的地点搜索接入，020 验证了模型选择与工具发现；现有配置只将 `maps_text_search` 加入白名单，报告没有天气工具调用与任务验收。此任务扩展同一个高德 MCP 服务，而非重新接入高德。使用户能自然语言询问指定城市天气，由 coordinator 按意图选择受控天气能力，独立 Worker 执行真实 MCP 查询，网页展示来源、城市、预报日期和结果，刷新后仍能查看。不要把天气变成所有任务必经步骤。

## 2. 先读哪些内容

`AGENTS.md`、`CLAUDE.md`、`docs/progress.md`、`docs/roadmap.md`、[执行与预算规则](../design/agent-execution-rules.md)、[数据保护与幂等规则](../design/security-and-idempotency.md)、[022 任务](022-agent-responsibility-structure.md)与报告、[地图地点契约](../../contracts/mcp/map-place-search.md)，以及当前 `backend/src/life_agent/agents/coordinator/`、`backend/src/life_agent/modules/capabilities/routing.py`、`backend/src/life_agent/tools/maps/places.py`、`backend/src/life_agent/core/config.py`、Worker/Run API、网页 Run 结果组件及相关迁移。执行前以最新代码为准。

高德[官方 MCP 能力说明](https://developer.amap.com/api/mcp-server/summary)列出按城市名称或标准 adcode 查询天气，返回预报；具体工具名、参数模式、返回结构必须通过当前服务真实 `initialize`/`list_tools`/`call_tool` 再确认，不以本文猜测代替发现。

## 3. 本次范围

- 增加单独的天气能力描述、模型决策与服务端校验，使天气单独请求可执行，地点查询/购物仍保持原路径；当模型选择多能力时沿用共享预算、白名单与停止条件，不增加固定的地点→天气→购物链。
- 在现有通用 MCP 客户端和高德服务配置上接入天气工具，按真实发现结果做明确工具白名单与 schema 校验。地点工具目前可能假定仅一个允许工具，扩展时调整选择逻辑，保持地点回归。禁用、未发现、错服务、schema 不兼容均不得绕过。
- 城市由用户确认的上下文或本轮明确输入得出；信息缺失或歧义时请求澄清，不猜默认城市。限制查询范围为上游实际支持范围。
- 对成功查询保存归属 Run 的天气快照，API/SSE/网页可重读；标注城市、天气日期、查询时间和真实数据来源，未知字段不补造。对错误、超时、空结果与过期结果明确展示，不把模型推测当成实时天气。
- 更新必要的配置示例、MCP 契约和开发说明。沿用现有高德凭据，不新增外部账号要求；若实际端点未暴露天气能力，记录真实发现证据并标记受阻。

边界：本次不实现旅行行程编排、穿衣推荐、购买决策、搜索引擎接入、RAG 或完整通用 Agent 平台。

## 4. 方案、接口与预算

coordinator 只负责识别需求与选择可用能力，Worker/工具适配层执行 MCP；不要把具体高德调用塞回 coordinator。能力注册信息描述输入、适用场景和服务工具对应关系，模型输出必须经服务端约束、实时发现交集及执行前复核。不得由模型指定服务地址或扩大工具权限。

沿用现有 Run 的租约、取消、fencing、模型轮次与跨 Agent 的共享调用/耗时预算；不在本任务假定新的固定数值。达到上限时终止并保留已完成结果及可读原因；外部返回内容视为不可信数据，不能修改工具白名单。真实服务的天气工具名以发现结果为准；若采用候选 `maps_weather` 配置，启动前确认确实存在且 schema 匹配。

对外保持现有 Run 创建、状态、事件和权限契约；新增天气结果结构及持久化字段由执行者据现有迁移模式选择，需兼容历史 Run 和任务版本。

## 5. 数据保护与幂等

天气信息本身通常是公开数据，但用户输入、任务关联与查询历史属于私有数据。天气快照必须绑定 owner/task/revision/run，所有 API、事件与网页查询沿用现有归属校验；密钥只在本地环境，日志与报告不得输出。结果持久化要按 Run/执行尝试约束，失租 Worker 不得覆盖新尝试，重复事件或重试不制造多个相互冲突的结果。天气查询为只读外部请求，可重试但可能消耗配额，不承诺外部 exactly-once。无需订单号或支付字段。

## 7. 验收标准

- 真实 MCP `initialize`、`list_tools` 和天气 `call_tool` 有可复查证据；记录真实城市、预报日期、来源和结果，不把 stub/健康接口算作真实验收。
- 自然语言天气请求由真实模型选择能力，Worker 完成受控调用；无城市时澄清且不调用；地点/购物请求不被强制路由到天气。
- 保存结果后，Run API/事件和浏览器刷新一致；历史 Run 可读；另一用户读写均被拒绝。
- 禁用工具、发现不匹配、错误/超时、空结果、取消/失租与预算耗尽均按现有停止语义处理，无编造天气、越权工具调用或重复覆盖。
- 地点搜索、商品查询以及现有动态表单和共享预算的相关回归通过。报告区分测试替身与真实服务，逐项列出未通过及原因。

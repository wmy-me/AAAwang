## 1. 目标与当前事实

018 已完成“在上海找礼品店”的受控 `map_places` Run、真实高德 MCP、独立 Worker、PostgreSQL 保存、网页刷新与跨用户隔离。购物商品路径继续使用 `shopping_agent` 和模拟商品 MCP。任务聊天中的地点选择仍依赖服务端关键词/句式，地图工具白名单固定在服务配置，尚未由当前任务和 Agent 职责生成。

本轮为已选购物任务建立受控的**能力选择**：主协调在直答/追问、商品发现与规划、地点查询之间按用户表达与当前任务状态选择，允许以后增加天气或网页搜索能力；后端对模型选择做 schema、身份、版本、能力注册和预算校验。保持既有 `map_places`、`shopping_agent` Run 及历史结果的兼容性。首版只开放当前已验证的商品和地图只读能力，不开放任意 URL、服务名、写工具、下单或支付。

读根目录 `AGENTS.md`、`CLAUDE.md`、[进度](../progress.md)、[路线图](../roadmap.md)、[意图路由设计](../design/intent-routing.md)、[安全与幂等](../design/security-and-idempotency.md)，以及 012、014、017、018 报告。核对 task turn API、现有 run 创建/Worker claim、`shopping_agent` LangGraph、`map_places` 分支、MCP tool registry 与网页展示。记录两条路径的输入、状态、预算、终态和旧 API 行为，再设计共享路由边界；不要靠把 `if 地图词` 扩展成更多关键词来冒充能力选择。

## 3. 约束与实现

1. **能力注册**：定义受信后端的能力描述，包含稳定 capability ID、适用 Agent/任务类型、输入 schema、可调用的服务与工具白名单、读写级别、超时、预算及结果类型。当前至少注册 `shopping_product_discovery` 与 `map_place_search`。MCP 发现工具后与配置批准的服务/工具交集取可见集，未注册或未发现的工具不可用；描述用于模型选择，执行器再逐次检查。新增服务应主要增加注册/适配配置，Graph 边按能力结果类型和状态路由，不硬编码远端 URL。
2. **决策与条件边**：在已选购物任务的受信上下文中，主协调决定回答、追问、调用允许的专业能力或根据结果汇总。对商品采买继续委派发现/规划路径；地点查找只查地图并给出处；同一轮同时要求“找店并给奖品方案”时，在共享预算内按需调用两类能力，结果分别展示并保留来源。缺城市或商品硬条件时先追问。不能把所有 Run 固定走地图→商品→规划；分支选择、执行结果和停止原因可观测。
3. **安全与失败**：模型输出只能引用当轮注册候选能力及其受控参数，后端从会话/任务/版本绑定身份。可疑或歧义选择进入追问或安全失败；禁止模型改变 `owner_id`、MCP URL、tool name、凭据或白名单。外部返回文本不授予工具能力。错误、空结果、取消、租约失效与旧版本均不产生伪造成功。保留 017 的目标条件冲突门禁与 018 的错误分类。
4. **预算与持久化**：实际模型请求、委派、MCP 尝试跨子 Agent 共享限额；开始调用前检查并计入，记录耗时和终止原因。现有 Run 可采用最小必要的能力决策/执行记录或新增契约，明确多能力同轮结果如何与 task/revision、Run、assistant 消息、地点证据和商品方案关联；事务、幂等键、fencing 与历史兼容不得退化。不得把一次提交拆成无法追踪的多次隐藏 Run。
5. **网页与来源**：网页对追问、地点证据与商品方案分别显示；地图真实地点、模拟商品及未知费用标记清晰。刷新后按服务端授权读取本轮决定与结果。旧 `GET /api/maps/places` 和既有历史 Run 继续可读。
6. **规模控制**：本轮不引入任意 MCP 自动执行、长期记忆、全场景通用任务规划器或大规模 Skill 系统。路线、天气、公开搜索和 P5 文档 RAG 分别按后续任务接入注册机制。

## 4. 验收

| 场景 | 通过标准 |
| --- | --- |
| 受控路由 | 普通奖品请求仅商品能力；“在上海找礼品店”仅地图能力；缺城市先追问；组合请求按需调用两类能力且分别标记来源 |
| 白名单 | 未注册、跨 Agent、动态发现但未授权的工具以及模型指定的 URL/凭据被拒绝；关停地图配置后商品路径继续可用 |
| 预算与故障 | 同一轮共享模型/远端调用上限；空结果、超时、取消、旧 Worker、并发/重复提交不会生成越权结果或重复写入 |
| 真实闭环 | 在真实 PostgreSQL、独立 Worker、DeepSeek、Java 模拟商品 MCP 和高德地图 MCP 上，至少验证商品、地点、追问各一条路径及一条组合路径；真实浏览器提交与刷新、双账号隔离通过 |
| 回归 | 018 `map_places` 及 015–017 的方案/目标版本路径兼容；相关 Python 测试、Ruff、迁移与 `alembic check`、前端 lint/build 通过 |

先定能力/Run 契约和预算，再实现条件路由、白名单、必要迁移及网页，再做真实服务验收。外部服务和真实模型不能运行时如实记录受阻项，不能以替身验证标记完整完成。提交对应报告并同步进度、路线图、任务索引后停止。

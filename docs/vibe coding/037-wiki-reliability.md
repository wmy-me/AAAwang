# 037：Wiki 接入稳定性与对话不中断

## 目标

让已有 Wiki 接入不会阻断普通聊天，并保证 Wiki 整理提交遵循现有 Worker 租约和取消规则；不扩展新文件类型。用户不需要手工测试，也不需要安装 Embedding。

## 已发现的问题（执行前按最新代码复核）

1. 036 迁移尚未执行；`worker/runner.py:_run_direct_answer_with_lease` 在普通直答前无条件查询 Wiki 表，表缺失或数据库查询异常时可能导致普通对话失败。应提供 Wiki 禁用或不可用时的安全降级；显式要求查询用户资料时，不能假装已查询成功或编造来源，应提示资料服务不可用。
2. `modules/wiki/service.py:index_document` 在 `db.commit()` 后，Worker 才检查 `lease_lost`；失租仍可能写入页面，与报告所述 fencing 不符。应在同一事务中依据数据库里的当前 Run/租约/fencing 进行原子校验后提交页面及状态；取消或失租不得提交过期结果。错误状态写入也要考虑租约与取消。外部模型调用不能承诺 exactly-once。
3. 目前每次直答都查 Wiki，且只有直答路径可用；此前用户要求由 Agent 按需决定是否使用资料。应将知识查询接入既有可信能力注册/意图决策，普通闲聊不查；显式要求查询资料必须走受控查询或给出明确失败，不扩展第二套 Agent 链。能力组合与权限遵循现有机制，不强制其他任务查询。
4. 目前每文档一个页面、按长度截断原文，不等于多文档累积 Wiki；状态、截断与来源必须如实展示。保留后续增量 Wiki 和 PDF/Word 的规划，不在本阶段扩充。
